# 灵溯（lingsu）项目运行说明

> 一句话：这是一套 K12 科创协作平台（网页）。下面先教你**怎么把它跑起来、打开浏览器看**；后面才是给开发者看的架构和运维细节，看不懂可以先跳过。

---

## 一、30 秒看懂（你最少要知道的）

- 项目分"前端网页"和"后端服务"，外加数据库等，全都装在 **Docker 容器**里（可以理解成一个个独立的小盒子，互不干扰）；项目控制台是宿主机上的独立进程，不装进 Docker。
- 你**不需要懂 Docker 原理**，照着下面的命令敲就行。
- 项目服务已经配好：可以由独立控制台统一启动/关闭，也可以直接使用 Docker 命令。
- 未配置模型密钥时，AI 功能处于**演示模式**；配置兼容 OpenAI Responses API 的服务商后可切换为真实模型。

---

## 二、第一次怎么跑起来（傻瓜四步）

### 第 1 步：打开"终端"，启动 Docker 的家（只需第一次，也可由控制台完成）

macOS 没有 Linux 内核，Docker 必须住在一台 Linux 虚拟机里。这台虚拟机叫 **colima**。打开 Mac 自带的"终端"App，粘贴：

```bash
colima start
```

- 第一次会下载并启动虚拟机，等它打印 `running` 字样即可（约几十秒到一两分钟）；也可以在控制台点击“启动 Docker”。
- **以后电脑重启过，只需再跑这一条**把虚拟机叫醒，docker 命令才能用。

> 验证：接着敲 `docker ps`，能列出容器（哪怕为空）就说明成功了。

### 第 2 步：进入项目文件夹，启动独立控制台

```bash
cd /Users/anzhi/Desktop/雷灵/星辰/lingsu
./scripts/console.sh
```

这条命令只启动 `127.0.0.1:8800` 控制台，不启动 Docker，不启动项目容器。浏览器打开 <http://127.0.0.1:8800>；控制台页面可以启动/停止/重启 Docker/Colima 和整个项目服务，停止项目不会关闭控制台。

### 第 3 步：通过控制台或终端启动项目服务

```bash
docker compose -p lingsu --profile dev up --build -d
```

- 如果你的项目放在别的文件夹，把上面 `cd` 后面的路径换成你的实际路径即可；也可以直接在控制台点击“启动项目”。
- 这条命令会一次性拉起：数据库、缓存、后端、异步任务、前端网页等共 8 个容器，并自动建好数据库表。
- 等待约 1 分钟，直到所有容器状态变绿（显示 `healthy` 或 `Up`）。
- `docker compose up/down` 不会启动或停止 8800 控制台。

> 验证：敲 `docker ps --filter "name=lingsu"`，看到 `lingsu-frontend-1`、`lingsu-backend-1` 等都是 `Up` 即可。

### 第 3.5 步（首次必做）：初始化演示数据

容器里**默认没有任何账号**。第一次必须手动播种，否则登录会一直提示"账号或密码错误"：

```bash
docker exec lingsu-backend-1 python manage.py seed_demo --reset
docker exec lingsu-backend-1 python manage.py seed_ai_agents --reset
```

- 这会创建三个演示账号（密码 `lingsu-demo-2026`）、演示学校、示例项目，以及 16 个 AI 助手模板。
- 日常 `up -d` 重启**不会**清空（数据存在 Postgres 卷里），不用重复跑。只有清空了数据库卷才需要重跑。

### 第 4 步：打开项目网页

在浏览器地址栏输入：

```
http://127.0.0.1:5173
```

### 项目状态控制台

控制台只绑定本机回环地址，不会暴露到局域网或公网。它不属于 Compose，不会被 `docker compose up/down` 自动启动或停止；可以用 `PORT=8801 ./scripts/console.sh` 修改控制台端口。停止/重启 Docker 或项目服务会要求二次确认。

然后用下面的演示账号登录项目网页（见下一节）。

## 三、怎么关、怎么重启（日常操作）

| 你想做的事 | 命令 |
| --- | --- |
| 关闭全部项目服务（数据保留，控制台继续运行） | `docker compose -p lingsu --profile dev down` |
| 只重启某一项（比如改了后端代码后） | `docker compose -p lingsu --profile dev restart backend` |
| 重启前端（改了网页代码后通常不用，会自动热更新） | `docker compose -p lingsu --profile dev restart frontend` |
| 彻底关掉 colima 虚拟机省电 | `colima stop` |

> 小提示：网页代码改了之后，容器里的 Vite 会自动热更新，**不用重启**；只有改了后端 Python 代码或依赖，才需要 `restart`。

## 五、AI 功能（默认演示模式，可切换测试模型）

- AI 模块代码已接好 OpenAI Responses API（在 `.env` 里填 `OPENAI_API_KEY` 即可切换为真实模型；部署环境也兼容读取 `$ARK_API_KEY`）。MVP 流程测试可使用 OpenRouter 兼容接口：设置 `OPENAI_BASE_URL=https://openrouter.ai/api/v1`、`OPENAI_MODEL=openrouter/free`。免费路由存在限流和模型可用性波动，只用于测试，不作为生产服务承诺。
- **演示模式**：当没填密钥时，AI 不会拒绝你，而是基于你的真实项目内容（题目、当前步骤、已写草稿、全部材料）生成**标注清楚的示例建议**，绝不会编造数据；"跨步骤一致性体检"则返回严格的 JSON 结果。界面上会显示「演示模式」标签。
- 内置 16 个 AI 助手模板；学生在 AI 中心可"关联到当前步骤"，任务页右侧有"材料助手"，项目页材料档案顶部有"跨步骤一致性体检"。

## 六、局域网 / 手机能访问吗？

- 前端跑在 Docker 里，colima 把端口转发到一台虚拟机的 IP，**同一 WiFi 下的手机/其他电脑通常访问不到**宿主局域网 IP。
- 只想在自己这台 Mac 上看：用上面的 `127.0.0.1:5173` 即可。
- 需要给同网段演示：另有宿主原生方式（`scripts/dev-frontend.sh`，绑 `0.0.0.0`，但需先停掉 Docker 前端容器避免 5173 冲突）；真外网可用 ngrok 等隧道。

## 八、架构与端口（开发者参考）

| 组件 | 技术栈 | 容器名 | 容器内端口 | 宿主访问端口 |
| --- | --- | --- | --- | --- |
| 前端 | Vue3 + Vite + TS + Element Plus + Pinia | `lingsu-frontend-1`（dev profile） | 5173 | http://127.0.0.1:5173 |
| 后端 API | Django 5.1 + DRF + gunicorn | `lingsu-backend-1` | 8000 | http://127.0.0.1:18001 |
| 数据库 | PostgreSQL 16 | `lingsu-postgres-1` | 5432 | （容器内） |
| 缓存/队列 | Redis 7 | `lingsu-redis-1` | 6379 | （容器内） |
| 异步任务 | Celery + Celery Beat | `lingsu-celery-1` / `lingsu-celery_beat-1` | — | — |
| 文档转换 | Gotenberg 8 | `lingsu-gotenberg-1` | 3000 | （容器内） |
| 文件杀毒 | ClamAV | `lingsu-clamav-1` | 3310 / 7357 | （容器内） |

**关键点**：后端容器内 gunicorn 绑 `0.0.0.0:8000`，宿主通过 `BACKEND_BIND=127.0.0.1:18001` 映射出来。前端容器与后端同属 `lingsu` 的 docker 网络，Vite 把 `/api` 代理到容器内的 `http://backend:8000`（见 `frontend/vite.config.ts` 与 `docker-compose.yml` 的 `VITE_API_PROXY_TARGET`）。

## 九、常用运维命令（开发者参考）

在容器内执行 Django 命令的统一前缀：

```bash
docker exec lingsu-backend-1 python manage.py <command>
```

| 用途 | 命令 |
| --- | --- |
| 查看未生成的迁移 | `docker exec lingsu-backend-1 python manage.py makemigrations --check --dry-run` |
| 生成迁移文件 | `docker exec lingsu-backend-1 python manage.py makemigrations core` |
| 应用迁移 | `docker exec lingsu-backend-1 python manage.py migrate` |
| 重建 AI 模板 | `seed_ai_agents --reset`（幂等，覆盖全局模板） |
| 重建演示数据 | `seed_demo` |
| 跑后端测试 | `docker exec lingsu-backend-1 python manage.py test apps` |
| 查看后端日志 | `docker logs -f lingsu-backend-1` |
| 查看 Celery 日志 | `docker logs -f lingsu-celery-1` |

前端（在 `frontend/` 目录，宿主原生方式）：

```bash
npm run dev     # 开发服务器
npm run build   # 类型检查 + 生产构建
npm test        # 运行 vitest 单测
```

## 十、关键配置（`.env`，开发者参考）

| 配置项 | 当前值 | 说明 |
| --- | --- | --- |
| `BACKEND_BIND` | `127.0.0.1:18001` | 后端宿主映射端口 |
| `POSTGRES_DB` / `POSTGRES_USER` | `lingsu_integration` / `lingsu` | 数据库名与用户（重建容器前务必与数据卷一致） |
| `VITE_API_PROXY_TARGET` | `http://backend:8000`（容器内） | 前端开发代理目标；Docker 方式下前端经 docker 网络直连后端，不依赖宿主 18001 |
| `OPENAI_API_KEY` | （空） | 填空则进入演示模式；填入即启用真实模型。密钥只放后端 `.env` |
| `ARK_API_KEY` | （空） | 部署环境密钥别名；仅在 `OPENAI_API_KEY` 未设置时读取，绝不返回前端 |
| `OPENAI_BASE_URL` | （空） | 可选兼容接口地址；OpenRouter 测试使用 `https://openrouter.ai/api/v1` |
| `OPENAI_MODEL` | `gpt-4.1-mini` | 默认模型；OpenRouter 免费测试使用 `openrouter/free` |
| `CORS_ALLOWED_ORIGINS` | 含 `localhost:5173` 等 | 跨域白名单 |
| `DJANGO_DEBUG` | `1` | 开发模式（生产必须关闭） |

## 十一、已知坑与排错（开发者参考）

1. **后端容器无代码挂载**：`backend` 服务从镜像运行，本地改后端代码后必须 `docker cp` 进容器再重启，否则不生效：
   ```bash
   docker cp backend/apps/core/foo.py lingsu-backend-1:/app/apps/core/foo.py
   docker compose -p lingsu --profile dev restart backend
   ```
   容器内生成的新迁移也要 `docker cp` 回主机，否则重建镜像会丢迁移。
2. **colima 端口转发陈旧**：若配置正确、容器内自测对、但宿主端口访问命中旧行为，多半是 colima 转发驻留旧容器。轻量解法：换一个宿主端口。
3. **前端依赖（package.json）变动**：需在容器内重装再重启：
   ```bash
   docker compose -p lingsu --profile dev exec frontend npm install
   docker compose -p lingsu --profile dev restart frontend
   ```
4. **Postgres 凭证**：实际库名/用户是 `lingsu_integration` / `lingsu`，不是早期文档里的 `kechuang`。重建容器前确认 `.env` 与数据卷一致，否则后端起不来。
5. **磁盘满导致 colima VM 损坏**：宿主磁盘满会损坏 qcow2，表现为 `input/output error`。需 `colima delete -f && colima start` 重建。
