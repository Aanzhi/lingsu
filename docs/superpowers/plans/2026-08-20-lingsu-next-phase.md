# 灵溯下一阶段实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将当前已可运行的核心业务平台推进到可稳定试点、可持续迭代的版本。

**Architecture:** 先修复环境与回归基线，再补齐 AI 工作台中直接影响学生使用效率的交互，最后完成材料处理、E2E、CI 和生产验收。保持现有 Vue/Pinia + Django/Celery 架构，不在本阶段做大规模重构。

**Tech Stack:** Vue 3、TypeScript、Vitest、Django REST Framework、PostgreSQL、Celery、Redis、Docker Compose、Playwright。

---

## 阶段一：恢复可重复的开发与测试基线

目标：任何开发者都能用同一套配置启动，并能确认数据库迁移和测试结果可信。

- [ ] 统一 `.env` 与 `.env.integration` 的数据库命名、端口和密码说明，明确默认本地环境与集成环境的使用边界。
- [ ] 重建后端镜像并执行完整迁移，确认 `0032`—`0036` 均已应用。
- [ ] 修复后端测试库与最新模型不一致的问题，重新运行 157 项后端测试。
- [ ] 处理 AI 服务状态测试中 `demo_mode` 与 `not_configured` 的契约差异，固定 API 返回语义。
- [ ] 增加启动检查：数据库连接、迁移状态、Celery、Gotenberg、ClamAV 均异常时明确报错。
- [ ] 验收标准：一条命令启动；`/api/health/` 返回 `ok`；前端 75 项和后端 157 项测试全部通过。

## 阶段二：补齐 AI 工作台的高价值缺口

目标：学生不离开项目上下文即可完成“选择 Agent → 生成 → 核验 → 保存到指定材料草稿”。

- [ ] 对话重命名：在 `frontend/src/pages/shared/AICenter.vue` 增加重命名入口，调用现有对话更新接口，并补 Vitest 测试。
- [ ] 保存目标材料选择：将当前默认保存第一份材料改为明确选择材料，后端校验材料属于当前项目且允许写入。
- [ ] 材料引用：允许从当前项目材料列表选择引用项，生成请求传递引用材料 ID，后端按 Agent 契约限制读取范围。
- [ ] 附件入口：先支持已有附件上传链路的引用，不在本阶段新增独立存储协议；生成前显示文件名、扫描状态和移除操作。
- [ ] 上下文抽屉：显示当前任务、材料、论文类型和 Agent 允许范围；禁止跨项目切换上下文。
- [ ] 失败恢复：生成失败保留输入内容，支持重试，并展示配额不足、服务未配置、文件未扫描等明确原因。
- [ ] 验收标准：多对话新建/切换/重命名/归档、Agent 选择、项目绑定、材料选择保存、失败重试均有自动化测试。

## 阶段三：完善材料与报告生产链路

目标：上传后的材料可被可靠处理，报告导出过程可观察、可重试。

- [ ] 为 PDF、DOCX、TXT 建立文本提取服务；记录解析状态、失败原因和文本版本。
- [ ] 接入 OCR 任务并通过 Celery 执行，前端显示排队、处理中、完成、失败四种状态。
- [ ] 将解析文本纳入 AI 上下文，但保留项目权限、材料版本和学校隔离约束。
- [ ] 完善报告导出状态：排队、生成 DOCX、转换 PDF、完成、失败；失败时提供重试入口。
- [ ] 验收标准：500MB 限制、分片上传、病毒扫描、解析失败恢复和报告导出失败恢复均有接口测试。

## 阶段四：建立浏览器回归和 CI 门禁

目标：关键用户链路不再依赖人工点击。

- [ ] 使用 Playwright 增加登录与角色路由链路。
- [ ] 增加学生“创建项目 → 填写材料 → 提交 → 教师退回 → 学生重提 → 教师通过”链路。
- [ ] 增加学校授权、配额和跨学校不可见链路。
- [ ] 增加 AI 工作台多会话、流式生成、保存材料草稿链路。
- [ ] 配置 CI：前端类型检查、Vitest、构建、后端测试、迁移检查和 E2E。
- [ ] 验收标准：主分支合并前所有门禁通过，失败时能定位到具体测试链路。

## 阶段五：试点与生产验收

目标：完成小范围学校试点所需的安全、运维和可访问性检查。

- [ ] 配置正式域名、HTTPS、Secure Cookie、HSTS 和生产密钥，执行 `check --deploy`。
- [ ] 完成一次隔离环境 PostgreSQL + 媒体卷备份恢复演练。
- [ ] 增加服务历史状态、异常告警和 Celery 失败监控。
- [ ] 做键盘操作、焦点、对比度、窄屏布局和 1280/1440 宽度验收。
- [ ] 做跨学校越权、私有附件下载、AI 配额绕过和教师审核权限专项测试。
- [ ] 输出试点操作手册和故障处理手册。
- [ ] 验收标准：试点环境连续运行观察期内无 P0/P1 问题，恢复演练和安全专项全部留存记录。

## 优先级与节奏

1. 先完成阶段一，解除“测试结果不可信”和“重启配置不一致”。
2. 阶段二优先做材料选择保存、对话重命名、上下文约束，再做附件/材料引用。
3. 阶段三与阶段四并行推进，但任何 AI 新能力必须同步增加测试。
4. 阶段五作为试点前门禁，不以“页面能打开”作为完成标准。
