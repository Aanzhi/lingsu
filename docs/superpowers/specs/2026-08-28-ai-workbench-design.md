# 灵思 AI Workbench 设计规格

## 设计目标

学生进入灵思 AI 后，应能直接开始一段与研究阶段相关的对话。页面的主任务是“写下问题并获得下一步建议”，而不是让学生先理解 Agent、上下文范围或一组技术配置。

本规格以已确认的 WorkBuddy 式线框为视觉基准，但保留灵溯现有的浅色背景、苔绿色和学生工作台左侧导航。线框只定义结构与状态，不复制第三方品牌、机器人素材或宣传文案。

## 页面状态

### 新建对话态

新建态是一个完整的工作台启动页，垂直层级固定为：

1. 顶部标题区：灵思 AI、当前模式说明、只读项目上下文和历史会话入口。
2. 三段模式切换：开题、研究、成果表达。
3. 一组不超过三个的轻量意图按钮，帮助用户快速填入一句可发送的问题。
4. 一个统一的大 Composer。

开题模式不绑定项目。研究和成果表达自动绑定 URL 指定项目、当前主项目或最近进行中的项目；学生不能在此处切换项目，项目切换从项目页面或明确的 URL 上下文完成。

新建态不显示 Agent 名称、Agent 胶囊、工具搜索、材料引用、上下文抽屉、前置问卷或空白结果卡。平台模板仍在后台按模式自动解析，发送请求时继续携带真实 agent_key。

### 聊天进行态

发送第一条消息后，页面切换为沉浸式聊天工作区：

1. 轻量顶栏：灵思 AI、当前项目/模式、一个“新建对话”入口。
2. 最大化消息区域：用户消息右侧浅苔绿色气泡，AI 消息左侧正文流。
3. 底部固定 Composer：只保留输入、发送和停止生成。

聊天态隐藏模式切换、意图按钮、Agent 信息、历史列表、项目选择和上下文说明。只有消息区域滚动，页面外层不出现第二个滚动容器。

## 三种模式

- 开题：整理观察，形成研究问题和开题草稿；生成结果必须由学生确认后才允许创建项目。
- 研究：围绕当前项目的任务、材料、实验记录和研究分析推进下一步。
- 成果表达：围绕已完成或接近完成的项目整理摘要、展示内容和答辩表达。

三个模式共用同一套消息流、Composer 和错误/加载状态，只切换标题、说明、默认 Agent 和快捷意图。快捷意图不是表单，不会要求学生逐项补充信息。

## 结果与真实业务边界

普通 AI 回复保持正文流，不包裹成大卡片。只有结构化结果需要学生确认、编辑、复制、重新生成、保存为材料草稿或创建开题项目时，才出现轻量结果操作区。

结果卡不向学生暴露技术模板名；界面使用“开题草稿”“研究建议”“成果表达建议”等用户语言。任何写入项目、材料或审核流程的动作都必须由学生明确确认，AI 不自动提交、审核或公开。

## 历史会话

历史会话是新建态中的一个入口，不占用主画布。打开后使用现有会话接口加载、筛选和恢复会话；恢复会话后进入聊天态。聊天态只保留“新建对话”，避免把历史管理和当前对话混在一起。

## 响应式边界

本轮只验收 PC 端 1280px 和 1440px。内容沿用方案 B 的工作区宽度，不产生横向滚动；聊天态固定工作区高度，只有消息区域允许纵向滚动。
