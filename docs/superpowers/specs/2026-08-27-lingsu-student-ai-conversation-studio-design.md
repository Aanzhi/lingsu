# 灵思 AI Conversation Studio 设计规格

## 状态

- 设计方向：已确认，采用第 3 个视觉方向 Conversation Studio。
- 适用页面：学生端 `/student/ai`。
- 关键补充约束：学生工作台左侧导航默认收起为图标栏。

## 1. 目标

把学生端灵思 AI 从“页面上方有标题、页面中间有模式切换、底部有孤立输入框”的简陋空状态，改成一个专业、聚焦、可立即开始工作的研究对话空间。

页面打开后，学生应能在一眼内确认：

1. 当前处于开题、研究还是成果表达阶段；
2. 当前项目是什么；
3. 当前由哪个 AI 助手提供建议；
4. 可以直接问什么，以及从哪里开始输入。

## 2. 范围与非目标

### 本轮范围

- 重做 `/student/ai` 的新会话和已有会话布局、间距、层级、空状态及输入区表现。
- 在空会话中增加 3 个模式相关的示例问题，点击后复用现有发送流程。
- 在对话画布顶部显示当前 Agent 身份及简短说明。
- 学生工作台导航增加收起/展开控制，默认收起并记忆用户选择。
- 补齐桌面端 1280px、1440px 以及小屏下的布局与焦点态。

### 非目标

- 不新增数据库模型、API 接口或权限规则。
- 不改变会话、消息、流式生成、停止、失败重试、刷新恢复和结果确认行为。
- 不自动创建项目、保存材料、提交成果或通过审核。
- 不把教师端、平台端导航改成默认收起。
- 不新增第二套侧栏、复杂材料选择器、数据看板或营销性内容。

## 3. 信息架构

页面保持学生工作台的全局顶部栏和左侧导航，但 AI 页面主区调整为单一垂直工作流：

```text
学生工作台
├── 默认收起的图标导航（可展开）
└── 灵思 AI 主区
    ├── 页面标题 / 当前项目 / 历史会话或新建对话
    ├── 开题 / 研究 / 成果表达
    ├── 当前 Agent 身份条
    ├── 对话画布
    │   ├── 空会话欢迎态 + 三个示例问题
    │   └── 已有消息 / 排队 / 生成中 / 失败重试 / 结果确认
    └── 唯一主输入区
```

空会话和已有会话使用同一套页面骨架，只替换对话画布内容，避免模式切换时出现两种完全不同的页面结构。

## 4. 视觉与布局

### 4.1 视觉基调

- 继续使用现有 `tokens.css` 的 `--ivory`、`--paper`、`--moss`、`--sage-soft` 和系统无衬线字体。
- 页面背景使用浅象牙色，主要对话画布使用暖白色；用间距、细分隔线和轻微表面色区分层级。
- 只保留一层主要对话画布和一个输入区，不使用卡片套卡片。
- 正文基准字号 14px，辅助文字不低于 11px；标题、按钮和状态文字建立清晰字号层级。
- 重点按钮使用苔绿色实底，次要操作使用白底细边框；焦点状态使用统一 focus ring。

### 4.2 页面主区

- 主区使用 `minmax(0, 1fr)` 的高度布局，充分利用首屏高度，取消当前新会话中输入框下方的大块空白。
- 标题区显示“研究工作台 / 灵思 AI”，右侧保留当前项目上下文和历史会话入口。
- 模式切换横向占据主内容宽度，保留三种模式，允许显示简短模式说明但不增加额外表单。
- Agent 身份条紧接模式切换，显示圆形文字标记、助手名称、在线/可用状态和一句职责描述；Agent 数据仍来自现有模板接口。
- 对话画布成为首屏的主要视觉中心，空态内容垂直居中但不强制占满整页；已有消息时只让消息流滚动。
- Composer 固定在对话画布底部附近，保持当前 Enter 发送、Shift+Enter 换行、发送/停止状态和可选材料引用能力。

### 4.3 空会话内容

根据模式提供三条轻量示例问题：

- 开题：把观察整理成研究问题、寻找可记录的变量、生成可执行的开题思路。
- 研究：拆解当前研究任务、设计下一步实验、整理已有证据。
- 成果表达：提炼项目亮点、生成展示提纲、模拟答辩提问。

示例问题只调用现有 `sendMessage`，不绕过会话创建、当前项目校验或 Agent 校验。资源尚未就绪时示例问题保持禁用。

## 5. 导航收起行为

### 5.1 桌面端

- 仅学生 `WorkspaceShell` 开启可收起能力；教师和平台端维持现状。
- 默认状态为收起，宽度约 72px；展开状态使用现有约 232px 宽度。
- 收起时隐藏分组标题、文字标签和内容资源子导航，仅保留图标、活动态背景和 tooltip/title。
- 展开/收起按钮放在导航底部，具有明确的 `aria-label` 和 `aria-expanded`；图标栏不能依赖颜色才能识别当前页面。
- 状态使用浏览器本地存储记忆，刷新和页面跳转后保持；不存在或无法读取偏好时回退到收起。

### 5.2 响应式

- 1280px、1440px 为主要验收尺寸。
- 860px 以下导航恢复为横向可滚动的文字导航，避免图标栏在小屏上丢失可发现性。
- AI 主区在窄屏下变为单列，模式切换和 Agent 身份条允许换行，Composer 保持可用触控高度。

## 6. 数据与交互契约

- 保留现有路由参数：`mode`、`projectId`、`taskId`、`agent` 及历史兼容参数。
- 模式切换继续调用现有 `selectWorkbenchMode`，不自动创建空会话。
- 当前 Agent 使用现有 `modeAgents` / `currentAgent` 解析结果；接口加载失败时显示真实错误和重新加载动作，不伪造模板。
- 当前项目上下文继续由现有 `workspaceContextLabel` 提供；开题模式继续显示不绑定项目。
- 消息区保留用户消息、助手正文、排队/生成中、错误重试和 `AIResultCard` 确认动作。
- 新增的示例问题必须走和 Composer 相同的 `sendMessage`，重试不能复制用户消息。

## 7. 文件职责

- `frontend/src/layouts/StudentLayout.vue`：为学生工作台开启可收起导航能力。
- `frontend/src/components/WorkspaceShell.vue`：管理学生导航收起状态、本地偏好和切换按钮。
- `frontend/src/components/WorkspaceFrame.vue`：提供收起状态的布局 class/属性传递。
- `frontend/src/pages/shared/AICenter.vue`：编排统一页面骨架、Agent 身份条、空会话示例问题和已有消息画布。
- `frontend/src/components/ai/AIModeTabs.vue`：保持模式选择组件职责，调整展示密度和描述显示方式。
- `frontend/src/components/ai/AIWorkbenchComposer.vue`：保持输入、发送、停止和材料引用契约，仅做视觉层级与尺寸调整。
- `frontend/src/styles/foundations.css` / `frontend/src/styles/responsive.css`：补充通用导航收起及响应式布局规则。
- `frontend/src/aiCenterUI.test.ts`、`frontend/src/aiWorkbenchLayout.test.ts` 及新增导航状态测试：锁定页面结构、空态入口、收起语义和现有行为边界。

## 8. 可访问性与状态

- 导航收起按钮、模式 tab、示例问题和发送/停止按钮必须有可读的 accessible name。
- 收起导航不删除链接的语义名称；使用 `aria-label`/`title` 补足图标栏信息。
- 保留现有 `aria-live`、`aria-busy`、错误 `role="alert"` 和资源加载 `role="status"`。
- 空会话、资源加载、项目缺失、Agent 缺失、排队、生成中和失败状态都在同一对话画布内稳定呈现。
- 所有新按钮沿用项目现有键盘焦点样式，不以 hover 作为唯一反馈。

## 9. 验收与测试

### 自动化

- 新增/更新静态结构测试，验证统一工作区骨架、当前 Agent 身份条、三个模式示例问题和导航收起语义。
- 验证导航默认收起、点击切换、刷新偏好读取以及教师/平台端不受影响。
- 保持现有前端单元测试、TypeScript 检查和生产构建全部通过。

### 浏览器验收

- 访问 `/student/ai?mode=research&projectId=91&taskId=500` 时首屏不出现大块无意义空白。
- 默认看到图标导航、研究模式、当前助手、可开始对话的欢迎态和底部 Composer。
- 展开导航后文字标签与子导航恢复，收起后 active 状态、tooltip 和键盘焦点仍可识别。
- 切换开题/研究/成果表达时保留有效项目参数和页面骨架。
- 输入、发送、停止、失败重试、历史会话和结果确认不改变业务行为。
- 在 1280px、1440px 和窄屏下分别检查无水平溢出、无元素遮挡、Composer 可操作。
