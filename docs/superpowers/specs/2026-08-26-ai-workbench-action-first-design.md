# 灵思 AI Workbench「研究动作优先」设计规格

## 设计状态

- 视觉方向：A「研究动作优先」已由用户确认。
- 适用范围：学生端 `/student/ai`；教师端审核详情继续使用独立的审核副驾驶，不把教师审核流程迁入学生工作台。
- 设计基准：灵溯方案 B 的浅色纸白背景、苔绿色强调、系统无衬线字体、66px 顶栏和现有学生工作台侧栏。
- 约束：仅适配 PC 端 1280px 和 1440px；不复制 WorkBuddy 品牌、机器人素材、深色主题或宣传文案；不改变数据库、AI 接口、权限和审核规则。

## 1. 需要解决的问题

当前 AI 页面已经拥有模式、Agent、历史会话、项目上下文和消息发送能力，但这些功能被分散在多个层级：

1. 页面首屏标题区域过高，实际输入区被推到下方，用户不能快速判断“现在能做什么”。
2. 三种模式的视觉结构不完全一致，Agent 选择更像后台筛选器，不像可直接执行的研究动作。
3. Agent 菜单嵌在对话容器内部，容易被 `overflow` 裁切，弹层在 1280px 下显示不完整。
4. 研究模式的项目、任务和材料上下文没有在首屏形成稳定的可见锚点。
5. 页面加载依赖项目、Agent、会话数据全部返回后才完整显示，刷新时容易出现长时间空白。
6. “补充信息”类表单和逐步追问会把用户从当前任务带离；用户选择 Agent 后应直接输入目标，不再额外填写一套隐藏表单。

## 2. 页面信息架构

AI 页面仍然位于学生工作台侧栏的“灵思 AI”入口中，保留左侧导航和全局顶栏。只重新组织右侧工作区：

```text
学生工作台顶栏（66px）
├── 学生侧栏（232px，保持现有导航）
└── AI 工作区
    ├── 工作台头部：灵思 AI、当前项目、历史、上下文
    ├── 模式栏：开题 / 研究 / 成果表达
    ├── 研究动作栏：左右箭头 + 当前模式的 Agent 动作
    ├── 空会话启动态 或 消息流态
    └── Composer：统一输入、引用、发送/停止
```

### 2.1 工作台头部

头部压缩为一行上下文工具栏和一个轻量标题区：

- 左侧显示“灵思 AI”和当前模式短说明。
- 当前项目在右侧以清晰的项目上下文标签显示；开题模式显示“未绑定项目”。
- 历史会话和项目上下文各保留一个入口，默认以抽屉打开，不挤压主对话宽度。
- 消除指向当前页面的重复“打开工作台”或“历史对话”入口。

### 2.2 模式栏

三个模式必须使用同一结构、同一尺寸和同一交互规则：

| 模式 | 用户看到的目标 | 项目上下文 | 允许的结果 |
| --- | --- | --- | --- |
| 开题 | 从观察整理研究问题和开题草稿 | 不绑定项目，不读取材料 | 可编辑的开题草稿；确认后创建项目 |
| 研究 | 推进当前项目的任务、材料和实验 | 绑定一个当前项目，可选当前任务 | 建议、材料草稿、实验日志草稿、报告内容 |
| 成果表达 | 整理已完成成果并准备展示 | 绑定已完成或接近完成的项目 | 摘要、展示提纲、答辩问题和成果介绍 |

路由继续使用 `mode=opening|research|defense`，旧 `brainstorm` 只做兼容映射。模式切换只改变路由和上下文，不创建新会话消息。

## 3. Agent 设计

### 3.1 用户目标优先

Agent 不直接以平台模板名占据首屏，而是先展示可执行的研究动作。平台模板仍是唯一数据来源，前端只根据模板的角色、分组、启用状态、排序和允许上下文生成动作标签。

首屏最多展示 4 个动作，额外能力通过“更多能力”打开抽屉；横向轨道使用左右箭头切换，不显示滚动条。

建议的动作映射：

| 模式 | 默认动作 | 适合的模板能力 |
| --- | --- | --- |
| 开题 | 梳理研究问题 | 观察提炼、问题聚焦、开题报告、研究目标 |
| 开题 | 形成开题草稿 | 申报材料一致性、实施方案与进度 |
| 研究 | 完善当前材料 | 标题摘要、论文框架、扩写润色 |
| 研究 | 设计下一步实验 | 实验设计、方法检查、变量梳理 |
| 研究 | 整理实验日志 | 日志结构、证据整理、过程复盘 |
| 研究 | 检查证据与结构 | 参考文献、结果解读、材料一致性 |
| 成果表达 | 准备答辩表达 | 答辩模拟、展示提纲、成果摘要 |
| 成果表达 | 整理成果介绍 | 亮点提炼、项目简介、问答准备 |

动作胶囊选中后，必须在 Composer 顶部和输入区附近明确显示“当前 Agent · [名称]”。选择不会打开补充表单，也不会强制用户先回答 AI 的问题；用户可以立即输入自己的目标。

### 3.2 Agent 选择层级

- 快捷 Agent：模式栏下方的横向胶囊，最多 4 个可见。
- 更多能力：固定定位的右侧抽屉或带遮罩的浮层，脱离对话容器的 `overflow`，不被裁切。
- 搜索和分类仅用于快速定位模板；空结果需显示明确空状态。
- 当前 Agent 变化后只更新会话配置，不清除 Composer 草稿，也不伪造新的消息。

## 4. 空会话和消息流

### 4.1 空会话启动态

空会话首屏只回答三个问题：当前是什么模式、可以做什么、从哪里开始。

- 轻量标题“灵思 AI”，不使用大面积宣传性 Hero。
- 模式说明与当前项目上下文并列展示。
- Agent 动作胶囊紧接在模式栏下方。
- Composer 占据主要视觉焦点，提供直接输入框、引用材料、权限范围和发送按钮。
- 开题模式不显示材料引用控件；研究/成果表达模式显示当前项目可引用材料数量。

### 4.2 消息流态

首次发送后：

- 收起空会话标题，只保留紧凑会话栏。
- 用户消息使用浅苔绿色轻量气泡；AI 消息使用正文流，不套厚重卡片。
- 结构化结果只有在需要“编辑、保存、创建、带入表单”时使用结果卡片。
- Composer 固定在主画布底部，宽度与消息正文对齐。
- 生成中显示停止；停止只中断前端读取，不把未完成响应标记为完成。
- 失败状态提供真实重试，不重复创建用户消息；刷新后按服务端会话状态恢复。

## 5. Composer 契约

三个模式共用同一个 `AIWorkbenchComposer`，只由上下文配置控制差异：

- 输入：多行文本，Enter 发送，Shift+Enter 换行。
- 当前 Agent：始终可见，避免用户不知道请求由谁处理。
- 材料引用：保存 `selectedMaterialIds: number[]`，展示标题只是视图层信息。
- 发送参数：

```ts
context_scope: {
  selected_materials: number[]
}
```

- 开题：隐藏项目和材料引用，后端拒绝任何项目、任务和材料上下文。
- 研究：绑定当前项目，可带入当前任务；材料只能来自当前项目且必须可读取。
- 成果表达：绑定已完成或接近完成的当前项目；不得自动提交公开申请。
- 权限范围：显示“仅读取当前项目”或“开题模式，不读取项目材料”，不展示模糊的默认权限文案。

## 6. 抽屉与上下文

### 6.1 历史会话抽屉

- 默认关闭，右侧打开，不改变主画布宽度。
- 支持搜索、新建、重命名、归档、恢复。
- 归档会话只读；恢复通过现有会话更新接口恢复后才可继续发送。
- 切换会话保留未发送 Composer 草稿，切换模式同样保留草稿。

### 6.2 项目上下文抽屉

- 展示当前项目、当前任务、可引用材料数量和权限范围。
- 材料选择使用 ID；清除选择后回到 Agent 默认上下文。
- 不安全、扫描中、扫描失败或跨项目材料不可选，也不可进入 AI 上下文。
- 开题模式不打开项目上下文抽屉，或仅显示“不绑定项目”的说明。

## 7. 数据加载和状态策略

页面不再等待所有接口完成后才渲染。加载分为三层：

1. **立即渲染**：顶栏、侧栏、标题、模式栏、Composer 外壳和当前路由中的项目占位信息。
2. **渐进填充**：项目列表、Agent 胶囊、历史会话和材料数量分别显示局部 skeleton；其中一项失败不阻塞其他区域。
3. **交互就绪**：Agent 和会话加载完成后启用选择与发送；发送期间仅禁用必要控件。

每个区域都需要有明确的加载、空、错误和重试状态。错误提示应说明当前能否继续，例如“Agent 加载失败，仍可查看历史会话；重试后可发送”。

## 8. 可访问性与布局验收

- 模式、Agent、历史、上下文、发送和停止控件均有可读名称和键盘焦点。
- 左右箭头在首尾状态正确禁用，不产生隐藏横向滚动。
- 抽屉打开时焦点进入抽屉，Escape 关闭并回到触发按钮。
- 1280px 和 1440px：内容区不出现页面级横向滚动；Agent 轨道不显示滚动条；菜单不被 Composer 或父容器裁切。
- 三种模式使用相同的 Composer 结构和主操作位置，只有文案、上下文和 Agent 列表变化。
- 页面不出现“补充信息”独立表单、无动作按钮或 Demo B 的宣传性描述。

## 9. 实施边界

本规格允许修改：

- `AICenter.vue` 的页面结构和状态编排。
- AI 工作台相关组件的布局、可见状态和交互细节。
- AI 专属共享样式和局部测试。
- 必要时补齐前端渐进加载和材料 ID 的现有接口参数。

本规格不允许修改：

- 数据库模型和迁移。
- 项目、任务、材料、审核和成果申请的核心业务规则。
- 自动提交材料、自动通过审核或自动公开成果。
- 教师审核权限和独立控制台。
- 既有真实登录、CSRF、流式响应和 AI 审计链路。

## 10. 设计验收清单

- [ ] 学生侧栏仍保留，AI 只重做右侧工作区。
- [ ] 三个模式同构，模式切换后 Agent 和上下文正确变化。
- [ ] 选中 Agent 在 Composer 中明确显示。
- [ ] Agent 选择层不被裁切，且不出现滚动条。
- [ ] 研究/成果表达显示真实项目上下文；开题不读取项目材料。
- [ ] 页面首屏先显示可操作骨架，再异步填充项目、Agent 和会话。
- [ ] 失败重试、停止生成、会话恢复和材料引用保留真实行为。
- [ ] 所有 AI 写入操作仍要求用户确认。
- [ ] 1280px、1440px 无页面级横向滚动和控制台错误。
