# 灵思 AI 简化工作台设计规格

## 状态

- 设计已在对话中确认，等待实现前文档复核。
- 本规格只覆盖学生端 `/student/ai` 的页面结构、交互和展示边界。
- 教师端审核副驾驶、平台端 Agent 模板管理和后端业务接口不在本轮重构范围内；它们继续保持现有真实权限和审计链路。

## 1. 背景与问题

当前灵思 AI 页面把模式、Agent、历史会话、项目上下文、材料引用、权限范围和研究输入同时放在首屏。用户进入页面后需要先理解工具结构，再决定在哪里输入问题，造成以下问题：

1. 页面信息层级过多，聊天输入框不是最明确的主入口。
2. 三种研究阶段的对话框和操作方式不够统一。
3. Agent 选择后没有始终清晰地显示在对话区，用户难以确认当前由哪个助手提供建议。
4. 研究输入被表现为多项补充信息或填空流程，与“直接对话辅助研究”的目标不一致。
5. 历史、上下文和材料控制项挤压了主画布，形成多个互相竞争的功能入口。
6. 一些展示内容来自早期 Demo，强调宣传性描述而不是当前任务和下一步动作。

本次设计以参考线框的空间关系为视觉方向，但不复制 WorkBuddy 品牌、机器人素材、深色主题或宣传文案。

## 2. 设计目标

- 让用户在页面打开后可以立即选择研究阶段、选择 Agent 并输入问题。
- 开题、研究、成果表达使用同一套对话布局，只改变模式说明、Agent 集合和项目绑定规则。
- 选中的 Agent 在聊天框顶部持续可见。
- 项目上下文由系统自动带入，减少重复填写；开题模式明确不绑定项目。
- 保留真实会话、流式响应、停止、失败重试和审计能力。
- 所有写入项目、材料、报告或审核表单的行为都需要用户确认。
- 继续使用灵溯方案 B 的浅色、苔绿色、系统无衬线字体和 PC 端布局。

## 3. 非目标与边界

- 不新增数据库模型，不改变现有 AI 会话、消息、日志和项目接口的业务规则。
- 不自动创建项目、不自动提交材料、不自动通过审核、不自动公开成果。
- 不在本轮实现新的教师审核 AI 能力；教师审核详情继续使用独立的审核副驾驶。
- 不将平台模板管理搬入学生工作台；学生端只读取启用且允许学生使用的模板。
- 不在学生工作台中引入新附件上传、复杂材料管理或项目编辑表单。
- 不处理移动端布局；验收基准为 1280px 和 1440px。
- 旧会话、旧查询参数和后端数据不删除，只通过兼容映射和新的页面展示规则接入。

## 4. 产品关系

灵溯负责真实研究项目的状态，灵思 AI 负责基于这些状态提供建议和草稿：

| 灵溯项目状态 | 灵思 AI 的作用 | 是否直接写入 |
| --- | --- | --- |
| 项目、章节、任务 | 帮助用户理解下一步并拆解问题 | 否 |
| 材料、实验日志、审核意见 | 提供可核对的修改建议和结构化草稿 | 否 |
| 开题观察与研究问题 | 协助形成开题草稿 | 仅在用户确认后创建项目 |
| 已完成成果 | 生成摘要、展示提纲和答辩练习 | 仅在用户确认后保存 |

AI 的回答默认是工作草稿，不代表业务状态已经改变。进入项目、保存材料草稿、创建项目或提交申请都必须通过明确的人工操作完成。

## 5. 页面结构

### 5.1 外层布局

`AICenter.vue` 继续作为普通学生工作台中的一个页面，保留已有全局 `WorkspaceShell` 和左侧导航。灵思 AI 页面不再创建第二套侧栏，也不使用独立的悬浮工作台壳层。

页面从上到下只有四个主要区域：

```text
学生工作台左侧导航
└── 灵思 AI 页面主区
    ├── 页面标题与当前项目标签
    ├── 三种研究阶段切换
    ├── 当前阶段 Agent 横向选择条
    └── 统一聊天区
        ├── 当前 Agent 标识
        ├── 对话正文 / 空状态 / 错误状态
        └── 输入框与发送按钮
```

页面主区使用方案 B 的内容宽度、间距、边框和圆角。对话区是唯一的主要操作容器，不再并列显示上下文卡、统计卡和研究输入卡。

### 5.2 顶部标题区

- 小标题：`研究工作台`。
- 主标题：`灵思 AI`。
- 描述只说明当前页面能做什么，例如“选择研究阶段和 Agent，直接开始对话。”。
- 右侧显示当前项目标签；开题模式显示“不绑定项目”。
- 不显示重复的历史会话按钮、查看上下文按钮或技术性权限标签。

### 5.3 模式切换

使用统一的三段式模式切换控件：

1. **开题**：从观察和兴趣整理研究问题与开题草稿。
2. **研究**：围绕当前项目的任务、材料和进度推进研究。
3. **成果表达**：围绕已完成或接近完成的项目整理摘要、展示和答辩内容。

三段控件尺寸、位置、状态和对话区完全一致。模式只影响当前上下文和 Agent 列表，不切换到另一种页面布局。

兼容规则：

- `mode=opening` 显示“开题”。
- `mode=research` 显示“研究”。
- `mode=defense` 显示“成果表达”，保留 `defense` 作为现有链接和会话的兼容值。
- 旧的 `brainstorm` 或 `researchQuestion` 参数只映射到开题模式，不出现在页面文案和导航中。

### 5.4 Agent 选择条

- Agent 数据继续来自平台 Agent 模板接口。
- 页面按当前角色、当前模式、启用状态和模板排序过滤可用 Agent。
- 首屏展示少量 Agent 胶囊；超过可视宽度时使用左右箭头移动。
- 不显示浏览器滚动条，不显示 Agent 搜索、分类筛选或“更多能力”入口。
- Agent 选择后立即更新当前 Agent，并在聊天框顶部显示 `当前 Agent · {名称}`。
- Agent 切换不要求用户补充表单，不通过多轮提问收集页面必填字段。
- 如果模板接口暂时不可用，保留统一的错误提示和重新加载动作，不伪造平台模板数据。

平台端仍可创建和调整模板；学生页面不维护完整 Agent 列表的重复副本。

### 5.5 统一聊天区

三种模式共用一套聊天区组件：

- 顶部只显示当前 Agent 和当前项目标签。
- 空会话中显示一句模式相关的简短提示，以及直接输入的提示语。
- 用户消息使用轻量苔绿色气泡。
- AI 消息使用正文流，不为每条回答叠加厚重卡片。
- 只有需要“保存、创建、带入表单或确认”的输出才使用紧凑结果操作区。
- 输入框固定在聊天区底部；页面不再出现另一个独立的大输入框。
- 输入框 placeholder 三种模式保持同一语气，不能要求用户填写现象、目标、限制条件等结构化字段。

## 6. 三种模式的行为契约

### 6.1 开题

- 不绑定项目、任务或材料上下文。
- 用户可以直接输入观察、兴趣或已有想法。
- Agent 负责帮助整理研究问题、方法和开题草稿。
- AI 可以给出结构化开题结果，但结果必须先进入可编辑确认区域。
- 只有用户明确确认后，才调用现有项目创建接口。
- 项目创建成功后，页面跳转到真实项目页面；失败时保留草稿和错误原因。

开题结果操作区最多提供：编辑、重新生成、复制、确认创建项目。它不呈现多步研究问卷。

### 6.2 研究

- 项目选择顺序为 URL `projectId`、当前用户主项目、最近进行中的项目。
- 有项目时自动绑定当前项目；URL 有 `taskId` 时同时绑定当前任务。
- 没有项目时只显示一条简短提示和“进入我的项目”动作，不在聊天中反复询问资料。
- AI 默认使用后端按权限装配的当前项目上下文。
- 用户可以直接询问任务、实验日志、证据、材料结构、数据分析或报告问题。
- AI 结果可以继续追问、编辑、复制或重新生成；保存为材料草稿前需要确认。

### 6.3 成果表达

- 通过 `mode=defense` 兼容进入，页面显示“成果表达”。
- 绑定完成或接近完成的当前项目；没有合适项目时显示项目选择提示。
- Agent 负责摘要、展示提纲、成果介绍和答辩模拟。
- 结果只能生成建议或草稿，不自动提交成果申请或公开展示。
- 保存结果时显示目标业务对象和确认操作，避免用户误以为已经公开。

## 7. 上下文与数据边界

### 7.1 前端路由契约

保留以下地址：

```text
/student/ai
/student/ai?mode=opening
/student/ai?mode=research&projectId=:id&taskId=:taskId
/student/ai?mode=defense&projectId=:id
```

模式或 Agent 切换更新查询参数时，应保留有效的 `projectId` 和 `taskId`，不拼接重复参数，不创建无效路径。

### 7.2 AI 请求

继续复用现有会话消息接口和流式接口。前端保留真实上下文参数的构造能力，但由于本轮不展示材料选择器，默认发送空的手动选择集合：

```ts
context_scope: {
  selected_materials: []
}
```

项目、任务和材料的默认上下文由后端根据当前用户、当前角色、当前项目和 Agent 模板权限装配。开题模式不得带入项目或材料上下文。

后端现有权限校验继续生效：跨项目材料、无权限材料、未完成安全扫描的附件和不允许当前 Agent 读取的内容不能进入上下文。

### 7.3 写入边界

以下动作保持明确确认：

- 开题草稿确认创建项目。
- AI 结果保存为材料或实验日志草稿。
- AI 结果带入研究报告或成果申请表单。
- 教师端 AI 结果写入审核评语草稿。

AI 不自动提交、不自动审核、不自动发布。重试只重新请求回答，不复制原用户消息。

## 8. 交互状态

### 8.1 首次加载

先渲染稳定的页面骨架：标题、三种模式、Agent 区和聊天框；项目标签、Agent 列表和历史消息分别在对应位置显示 loading 状态。接口请求期间不让整页空白。

### 8.2 空会话

空会话只展示：

- 当前 Agent。
- 一句当前模式提示。
- 直接输入问题的 placeholder。
- 发送按钮。

不显示研究问卷、权限卡片、上下文统计或重复的帮助卡片。

### 8.3 生成中

- 保留用户消息。
- 输入框禁用重复发送。
- 显示停止生成。
- 停止只中断前端流读取，不伪造成功消息；刷新后依据服务端状态恢复。

### 8.4 失败与重试

- 失败消息以内联方式显示在当前对话位置。
- 保留用户原问题。
- 重试复用原消息上下文，不再次创建用户消息。
- Agent、会话或网络加载失败时显示明确错误和单一重新加载动作。

### 8.5 模式和 Agent 切换

- 切换模式只更新当前模式、路由参数和 Agent 集合。
- 若目标模式已有最近会话，恢复该模式会话；没有则显示空会话。
- 不因每次切换自动创建空会话。
- 当前未发送的输入草稿在模式切换和 Agent 切换时保留在前端页面状态中。

## 9. 组件职责

实现时优先复用或收敛现有组件，避免继续增加并行壳层：

| 组件 | 职责 |
| --- | --- |
| `AICenter.vue` | 路由上下文、模式/Agent状态、会话发送和结果确认编排 |
| `AIModeTabs.vue` | 三种模式切换和 Agent 胶囊横向移动 |
| `AIWorkbenchComposer.vue` | 统一输入、发送、停止和生成状态 |
| `AIConversationMessage`（可从现有模板抽取） | 用户消息、AI 正文、失败重试和结果操作 |
| `AIDraftActions.vue` | 仅显示需要人工确认的保存/创建动作 |
| `AIToolPicker.vue` | 本轮从学生工作台移除首屏入口；保留组件仅供兼容或后续管理场景 |
| `AIConversationHistory.vue`、`AIContextDrawer.vue` | 不在本轮学生页面渲染；保留底层数据兼容能力 |

页面级 CSS 只保留工作台布局差异，基础按钮、输入框、状态和卡片继续使用共享样式。

## 10. 测试策略

### 10.1 单元测试

- 模式规范化：opening、research、defense 以及旧参数映射。
- 项目默认选择顺序和无项目 fallback。
- Agent 按角色、模式、启用状态和排序过滤。
- 三种模式使用同一个聊天容器和 Composer。
- Agent 选中后显示在聊天头部。
- 不再渲染研究输入表单、历史/上下文/材料选择入口。
- 重试不会重复用户消息；停止不会伪造完成状态。
- 开题结果确认创建项目需要显式操作。
- 研究和成果表达结果不能自动提交公开申请。

### 10.2 定向浏览器验收

每轮只运行与修改范围对应的测试：

- AI 模板、状态和组件变化：AI 相关单元测试。
- AI 路由变化：AI 路由和导航测试。
- 视觉布局变化：1280px、1440px 两个截图检查。
- 后端上下文或权限变化：对应 API/权限测试。

最后合并完成后再运行一次完整 E2E、前端构建和后端核心测试，不在每次小幅样式修改后运行全量测试。

### 10.3 视觉验收

- 页面打开后不出现整页空白等待。
- 左侧学生导航只出现一套，AI 页面不嵌套第二套侧栏。
- 三种模式的对话框尺寸、位置、边框和输入方式一致。
- Agent 超出可视范围时只有左右箭头，不出现滚动条。
- Agent 选择后聊天区明确显示名称。
- 1280px 和 1440px 无横向滚动、无内容截断和无布局错位。
- 不出现旧 Demo 宣传文案、补充信息填空或无效按钮。

## 11. 实施顺序

1. 以本规格为基线，补充或调整 AI 页面定向测试。
2. 收敛 `AICenter.vue` 的首屏模板，移除历史、上下文、材料选择和研究输入展示。
3. 调整 `AIModeTabs` 和 `AIWorkbenchComposer`，确保三个模式共用同一布局。
4. 将 Agent 选择结果显示到聊天头部，并保留平台模板动态过滤。
5. 保留真实发送、流式响应、停止、重试和开题确认逻辑。
6. 清理失效 scoped CSS 和重复样式，完成方案 B 视觉验收。
7. 运行定向测试、构建和 1280/1440 截图检查。
8. 定向测试通过后，再执行完整回归。

## 12. 验收结论

当学生能够完成以下最短路径时，本轮设计达标：

```text
打开灵思 AI
  → 选择开题/研究/成果表达
  → 选择该模式下的 Agent
  → 直接输入问题
  → 查看 AI 回复
  → 必要时人工确认保存或创建
```

用户不需要先理解复杂工具体系，也不需要通过填空或多轮追问才能开始。项目状态仍由灵溯真实业务页面维护，灵思 AI 只作为可确认的研究辅助入口。
