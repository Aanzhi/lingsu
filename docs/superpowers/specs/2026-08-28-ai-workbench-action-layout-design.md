# AI 工作台顶部与输入操作区布局优化设计

## 背景

学生端 AI 工作台的三个模式已经统一为同一套主 Agent 工作台，但当前页面的顶部上下文操作区和底部输入操作区仍然存在层级、对齐和间距不够稳定的问题：当前项目、历史会话、添加技能、快捷键提示和发送按钮容易挤在同一视觉层级中，项目名称或模式文案变化时也可能造成操作位置漂移。

本次设计采用已确认的 A 方案“上下分层”，只调整这两个区域的呈现方式，不改变工作台主布局、功能行为或移动端范围。

## 目标

- 顶部明确表达“当前工作上下文”，让当前项目成为主要信息。
- 将历史会话降级为独立的次级入口，减少与项目上下文的竞争。
- 底部形成稳定的三段式操作栏：技能、提示、发送。
- 在开题、研究、成果表达三个模式下保持相同的对齐规则和垂直节奏。
- 保留键盘发送、Skill 选择、历史会话打开和发送状态等现有行为。

## 非目标

- 不增加新的 AI 能力、Skill 或会话数据字段。
- 不改变三个主 Agent 的模式切换逻辑。
- 不改动对话历史筛选、标题生成和结果卡片逻辑。
- 不进行移动端布局设计或适配扩展。

## 设计方案

### 1. 顶部上下文操作区

顶部右侧保留当前项目胶囊作为主上下文，统一高度、内边距和最大宽度。项目名称过长时使用单行省略，避免挤压其他操作。

历史会话作为独立的次级文字入口，与项目胶囊保持固定间距和垂直基线。它继续使用原有打开历史抽屉的行为，只降低边框和视觉重量，不改变可访问名称、禁用状态或打开方式。

顶部操作区的布局职责固定为：

```text
当前项目上下文  →  历史会话入口
```

### 2. 底部输入操作区

输入框内容区域保持现有高度和占位文案。底部操作栏使用三段式横向布局：

```text
添加技能  ｜  Enter 发送 · Shift+Enter 换行  ｜  发送
```

左侧技能按钮保持内容宽度，并继续打开 Skill 选择器。中间快捷键提示占用剩余空间，在不同模式下不改变右侧发送按钮的位置。右侧发送按钮固定宽度和高度，发送中仍显示原有停止操作。

操作栏需要处理以下状态：

- 未输入时发送按钮保持禁用样式。
- 选中 Skill 后，技能名称允许截断但不推动发送按钮。
- 发送中保留停止操作和等待状态。
- 快捷键提示不参与点击，也不抢占技能和发送按钮的可用空间。

### 3. 统一间距规则

顶部操作区和底部操作栏分别使用统一的内部间距，不依赖模式文案长度决定位置。三个模式继续共用同一内容网格，避免仅开题模式拥有可伸展空间而导致输入框垂直位置不同。

## 组件边界与数据流

- `AICenter.vue` 负责顶部上下文操作区的结构和工作台级别的间距规则。
- `AIWorkbenchComposer.vue` 负责输入框底部操作栏的三段式排列、溢出和按钮状态呈现。
- 现有事件接口保持不变：`add-skill`、`send`、`stop` 和 draft 更新继续由 `AICenter.vue` 处理。
- 不新增后端接口或持久化逻辑。

## 验证方案

采用定向验证，不执行全量测试：

1. 增加或更新布局契约测试，检查顶部操作区和底部操作栏的结构、固定尺寸和不换行规则。
2. 运行 AI 工作台相关前端测试，覆盖模式布局、Composer、历史会话和结果卡片。
3. 执行前端类型检查与生产构建。
4. 在浏览器中分别打开开题、研究、成果表达三个空状态，确认项目/历史操作区和输入操作栏的水平、垂直位置一致。
5. 检查 `git diff --check`。

## 验收标准

- 用户能一眼区分当前项目上下文与历史会话入口。
- 添加技能、快捷键提示和发送在三个模式中保持同一行、同一基线和稳定的右侧位置。
- 长项目名或已选 Skill 不会造成发送按钮跳动或操作栏换行。
- 现有历史会话、Skill 选择、键盘发送、停止发送和禁用状态均保持可用。
- 不引入移动端适配范围或新的业务逻辑。
