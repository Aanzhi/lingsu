# 灵溯全项目 MVP 设计

## 1. 目标

面向单校试点，交付一个可以真实跑通青少年科创项目全过程的 MVP。学生能够创建项目、完成材料、使用 AI 辅助、提交教师审核、根据反馈修改、导出 DOCX/PDF 报告并申请公开案例；教师能够完成指导与审核；平台管理员能够发布赛事和平台公告，并完成公开案例治理。

MVP 的成功标准不是页面数量，而是一组试点账号能够连续完成一次端到端业务闭环，且关键数据、权限、异步任务和失败反馈可信。

## 2. 角色与最小能力

### 学生

- 注册、登录和修改密码。
- 创建项目，填写题目、研究问题与方案概要。
- 邀请同校学生组队，查看邀请状态。
- 按固定研究旅程查看任务、编辑材料和上传附件。
- 确认内容真实后提交材料。
- 查看教师退回意见，修改并重新提交。
- 在 AI 中心选择项目和 Agent，获得真实模型回复。
- 编辑 AI 生成草稿，并保存到明确选择的项目材料草稿。
- 在项目完成后导出 DOCX/PDF 报告。
- 申请将已完成项目发布为公开案例。
- 查看赛事、公告、审核反馈和成员通知。

### 教师

- 登录并查看待认领项目、已指导项目和待审核材料。
- 认领项目或将学生加入项目。
- 查看材料及附件，通过或退回，并填写审核意见。
- 审核学生的公开案例申请。
- 查看赛事、平台公告和通知。

### 平台管理员

- 管理学校启用状态、试点账号和基础配额。
- 创建、编辑和发布赛事。
- 创建、编辑和发布平台公告。
- 对教师初审后的公开案例执行发布、下线和再次发布。
- 查看基础服务状态与 AI 是否可用，不向前端暴露密钥。

## 3. MVP 业务闭环

### 项目与审核闭环

1. 学生创建项目并进入固定研究旅程。
2. 学生编辑任务材料，确认真实性后提交。
3. 指导教师在审核队列查看提交内容。
4. 教师选择通过，或填写原因后退回。
5. 被退回的材料保留历史版本；学生修改后重新提交。
6. 所需材料全部通过后，项目进入可完成状态。

### AI 辅助闭环

1. 学生创建或选择一个只绑定单一项目的 AI 对话。
2. 学生选择 Agent，填写必要输入并发送问题。
3. 后端沿用现有项目权限、Agent 契约、学校配额、审计和 Celery 任务流程。
4. 模型结果写入 AI 生成记录和对话消息。
5. 学生核验并编辑结果，明确选择目标材料后保存为草稿。
6. AI 不提交材料、不执行教师审核、不虚构实验数据和引用。

### 报告导出闭环

1. 学生从已审核材料发起报告导出。
2. Celery 生成 DOCX。
3. Gotenberg 将 DOCX 转换为 PDF。
4. 前端显示排队、处理中、完成或失败。
5. 完成后通过鉴权接口下载 DOCX 或 PDF；失败后允许重新发起。

### 公开案例闭环

1. 已完成项目的学生提交公开案例申请。
2. 指导教师进行一级审核，通过或退回并说明原因。
3. 平台管理员执行二级治理并发布。
4. 已发布案例对校内用户可见；管理员可下线，历史申请和审核记录保留。

### 赛事与公告闭环

1. 平台管理员创建并发布赛事或平台公告。
2. 学生和教师在内容中心查看已发布内容。
3. 未发布内容仅管理员可见；已停用内容不再出现在普通用户列表。

## 4. AI 测试接入方案

API  KEY 在系统中的 $ARK_API_KEY
MVP 使用现有 OpenAI Python SDK 和 Responses API 调用方式。新增 `OPENAI_BASE_URL` 配置，默认仍指向 OpenAI；本地测试设置为 `https://openrouter.ai/api/v1`，模型设置为 `openrouter/free`。

仅允许修改 AI 客户端初始化和环境配置，不改变以下业务逻辑：

- AI 请求权限与学校数据隔离。
- Agent 输入契约和项目上下文组装。
- 学校月度配额扣减。
- AI 生成记录、引用来源和审计记录。
- Celery 异步执行和 SSE 状态通知。
- AI 草稿保存到材料版本的规则。

免费 API Key 由项目所有者在服务商控制台创建，只写入未纳入版本控制的 `.env`。`.env.example` 仅记录变量名和示例地址，不包含真实密钥。免费模型只用于流程验证；限流或模型暂不可用时，页面显示可重试错误，不自动伪装为真实结果。

## 5. 架构边界

- 前端继续使用 Vue 3、Pinia、现有路由和 API 客户端。
- 后端继续使用 Django REST Framework，业务写操作沿用现有 workflow/service 边界。
- PostgreSQL 保存学校、账号、项目、材料版本、审核、案例、赛事、公告、AI 和导出记录。
- Redis/Celery 执行 AI、文件扫描和报告导出任务。
- 私有附件和报告继续通过 Django 权限接口下载。
- 不为 MVP 新增微服务，不替换数据库，不重写现有角色权限模型。

## 6. 错误处理

- 登录和权限错误必须显示明确原因，不能跳转到无关页面。
- 材料提交失败时保留学生输入，防止重复提交。
- 教师审核失败时保留审核意见并允许重试。
- AI 的 401、429、502、503 和超时统一映射为用户可理解的错误；配额扣减遵循现有业务规则。
- DOCX/PDF 导出失败保存错误状态，不能显示为已完成。
- 案例、赛事和公告写操作失败时保留表单内容。

## 7. MVP 不包含

- OCR 和扫描件文字识别。
- AI 附件直传、跨项目上下文和多模型管理页面。
- 自定义研究旅程设计器。
- 公开案例推荐算法、收藏、评分和外网匿名访问。
- 赛事报名、评审和获奖管理。
- 公告短信、邮件或第三方推送。
- 报告可视化模板编辑器和复杂图表排版。
- 多地域部署、自动扩缩容和企业级监控平台。

这些能力不阻塞单校 MVP 的核心流程。

## 8. 测试与验收

### 自动化测试

- 前端类型检查、Vitest 和生产构建必须通过。
- 后端全部 Django 测试必须在最新迁移创建的测试库上通过。
- 增加最小浏览器验收：登录、材料提交/退回/重提/通过、AI 生成并保存、报告导出、案例发布、赛事和公告可见性。

### 手工试点验收

使用学生、教师、平台管理员三个真实试点账号完成：

1. 管理员发布一项赛事和一条公告。
2. 学生创建项目并提交至少一份材料。
3. 教师退回一次，学生修改重提，教师通过。
4. 学生调用真实免费 AI，编辑结果并保存到指定材料草稿。
5. 学生导出可打开的 DOCX 和 PDF。
6. 学生申请公开案例，教师初审，管理员发布。
7. 其他学校账号无法读取该项目、附件、AI 对话或报告。

以上七项全部通过，即视为灵溯全项目 MVP 完成。
