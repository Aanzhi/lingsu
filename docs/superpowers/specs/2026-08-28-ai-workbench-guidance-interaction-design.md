# 灵思 AI 工作台引导步骤交互设计

## 目标

新建对话态的三张“灵思会这样推进”步骤卡不再只是静态说明。每张卡都要帮助学生进入一个明确的研究动作，并且与页面下方唯一的 Composer 形成直接关联。

## 已确认的交互

三张步骤卡统一采用“选择步骤 → 打开步骤工作框 → 编辑并生成”的流程：

1. 学生点击某一步，卡片进入选中状态并弹出独立的步骤工作框。
2. 步骤工作框展示该步骤的目标和结构化填空字段，不改写底部 Composer。
3. 学生逐项补充自己的观察、材料和目标；必填项完成后，点击“开始生成”才发起 AI 请求。
4. 生成请求继续使用当前模式、当前 Skill、懒创建会话和现有流式消息链路，结果进入正式对话记录。

每个步骤由字段配置驱动，字段包含标题、提示语和必填状态。例如“描述一个观察”包含“观察到什么 / 想弄清什么 / 已有证据或材料”。步骤工作框真正承载任务准备，不把底部 Composer 变成一段长提示词或前置表单。

## 模式模板

三种工作模式各自提供三份与阶段匹配的模板：

- 开题：描述观察、形成研究问题、确认开题草稿。
- 研究：说明当前任务、制定下一步方案、整理研究记录。
- 成果表达：说明要表达的成果、整理表达重点、确认展示内容。

模板只存在于学生端展示层，不新增 API、数据库字段或平台 Agent。真实发送内容仍由学生最终编辑后提交。

## 状态与可访问性

- 步骤卡使用真正的 `button` 语义，显示 hover、focus-visible 和选中样式。
- 选中状态通过 `aria-pressed` 暴露；按钮标签包含步骤标题。
- 步骤工作框使用真正的 `dialog` 语义，打开时聚焦第一个填空字段，关闭时不产生请求。
- 必填字段为空时“开始生成”不可用；生成时仅将字段值按字段标题组合为当前对话输入。
- 底部 Composer 的 draft 与步骤工作框的字段值相互独立；用户取消或关闭步骤工作框时，底部输入保持不变。
- 切换模式或切换会话时沿用现有 draft 保存/恢复逻辑；聊天开始后步骤区自然退出新建态。

## 边界

- 不改变三模式的页面布局和现有视觉密度。
- 不添加移动端专用布局。
- 不自动发送、不自动保存材料、不自动创建项目。
- 本轮只做前端交互和定向 UI 契约验证，不运行全量测试。

## 验收标准

在 PC 端新建对话态：

1. 三张步骤卡可通过键盘和鼠标触发。
2. 点击任一步后，该卡被明确标记为选中，并弹出对应的填空工作框；底部 Composer 内容不变。
3. 工作框的字段可逐项填写，必填项完成后点击“开始生成”，进入当前模式对话并显示 AI 输出。
4. 开题、研究、成果表达三种模式均使用各自的任务模板。
