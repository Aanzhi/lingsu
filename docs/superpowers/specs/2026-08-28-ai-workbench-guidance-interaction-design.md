# 灵思 AI 工作台引导步骤交互设计

## 目标

新建对话态的三张“灵思会这样推进”步骤卡不再只是静态说明。每张卡都要帮助学生进入一个明确的研究动作，并且与页面下方唯一的 Composer 形成直接关联。

## 已确认的交互

三张步骤卡统一采用“选择步骤 → 载入任务模板 → 编辑并发送”的流程：

1. 学生点击某一步，卡片进入选中状态。
2. 该步骤的完整任务模板载入 Composer 文本框，而不是只插入一句短语。
3. 文本框自动获得焦点，学生可以补充自己的观察、材料和目标。
4. 学生发送后继续使用当前模式、当前 Skill、懒创建会话和现有流式消息链路。

模板必须带有可填写的上下文结构，例如“当前任务 / 已有材料 / 希望得到的结果”，让点击行为本身能降低开始对话的门槛，同时不把 Composer 变成前置表单。

## 模式模板

三种工作模式各自提供三份与阶段匹配的模板：

- 开题：描述观察、形成研究问题、确认开题草稿。
- 研究：说明当前任务、制定下一步方案、整理研究记录。
- 成果表达：说明要表达的成果、整理表达重点、确认展示内容。

模板只存在于学生端展示层，不新增 API、数据库字段或平台 Agent。真实发送内容仍由学生最终编辑后提交。

## 状态与可访问性

- 步骤卡使用真正的 `button` 语义，显示 hover、focus-visible 和选中样式。
- 选中状态通过 `aria-pressed` 暴露；按钮标签包含步骤标题。
- 输入框聚焦由 Composer 暴露一个最小的 `focus()` 方法完成，不通过页面级 DOM 查询耦合实现。
- 切换模式或切换会话时沿用现有 draft 保存/恢复逻辑；聊天开始后步骤区自然退出新建态。

## 边界

- 不改变三模式的页面布局和现有视觉密度。
- 不添加移动端专用布局。
- 不自动发送、不自动保存材料、不自动创建项目。
- 本轮只做前端交互和定向 UI 契约验证，不运行全量测试。

## 验收标准

在 PC 端新建对话态：

1. 三张步骤卡可通过键盘和鼠标触发。
2. 点击任一步后，该卡被明确标记为选中，Composer 出现对应的多行任务模板并获得焦点。
3. 模板可编辑，发送按钮仍按原有 `draft` 状态启用并进入当前模式对话。
4. 开题、研究、成果表达三种模式均使用各自的任务模板。
