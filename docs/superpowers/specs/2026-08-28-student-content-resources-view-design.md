# 学生赛事信息与校内通知内容视图设计规格

## 已确认方向

采用方案 A：保留“赛事信息”和“校内通知”两个一级入口，使用同一套内容流骨架，但让页面目标明确区分：赛事用于判断是否参赛，通知用于阅读学校与平台安排。

## 设计目标

- 让页面在首次进入时就能看到真实内容，不用通过“筛选”按钮才能完成普通搜索。
- 让内容按完整宽度排列，消除当前三列窄卡片造成的大片空白和信息截断。
- 不增加后端没有支持的报名、收藏、报名跳转或详情路由按钮。
- 不把个人审核、邀请和项目状态变化混入公开通知；这些继续由消息中心承担。
- 1280px 和 1440px 下使用相同的内容起点、最大宽度和间距令牌。

## 赛事信息页

页面标题区下方是一个实时搜索框，搜索结果随输入更新，不显示无行为的“筛选”按钮。

内容区使用“重点赛事 + 赛事清单”结构：

1. 第一条赛事作为重点赛事，显示报名状态、报名截止时间、赛事日期、面向对象、标题和完整描述。
2. 其余赛事按统一列表行展示，左侧为日期，右侧为状态、标题、描述和关键时间。
3. 只有一条赛事时只显示重点赛事，避免同一记录重复出现。
4. 不再固定截断前三条；列表数量由接口响应决定。
5. 时间缺失时显示“时间待定”，不伪造日期；状态优先使用后端状态，缺失时根据报名截止时间推导。

## 校内通知页

页面标题区下方同样使用实时搜索框，随后展示一条纵向通知时间线：

- 每条通知包含来源标签、标题、正文和发布时间。
- 平台公告与学校通知使用不同来源标签，但复用同一视觉组件。
- 未读状态只用轻量标记表达，不额外增加跳转按钮。
- 删除“这里只展示公开发布的通知……”等重复解释，标题描述直接说明消息中心负责个人事项。
- 内容按接口顺序显示，不固定截断数量；没有结果时使用统一空状态。

## 共享视觉契约

- 页面使用 `resource-content-page` 内容流容器。
- 分区标题、数量、卡片、列表行和时间线使用方案 B 的共享边框、圆角、颜色和间距。
- 重点赛事是纸白卡片，使用浅苔绿色状态与日期强调；普通赛事为低密度列表行。
- 通知时间线使用左侧细线和节点，正文自然换行，不使用内部滚动容器。
- 页面只保留真实数据可表达的文本和状态，不复制设计 Demo 的宣传文案。

## 业务边界

- 继续复用 `getCompetitions` 和 `getAnnouncements`，不增加接口、字段或数据库模型。
- 教师端继续复用同一数据视图与筛选逻辑；标题和说明由现有角色上下文决定。
- 案例库、消息中心和项目页面不在本轮修改范围内。

## 验收标准

- 两个页面都保留独立一级路由，搜索输入可以即时过滤真实接口数据。
- 赛事页面没有三列窄卡、固定前三条或无行为筛选按钮。
- 通知页面没有重复范围说明，通知正文和日期对齐清晰。
- 1280px、1440px 无横向滚动、无内容遮挡、无内部列表滚动条。
- 空态、加载态和错误态继续可见，接口失败时不显示伪造数据。
