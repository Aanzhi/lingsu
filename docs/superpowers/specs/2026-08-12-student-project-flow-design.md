# 灵溯学生项目闭环设计

## 目标

把灵溯学生端从静态展示接入 Django API，完成从立项申请、项目激活、AI 辅助写作到开题材料提交的可持久化最小闭环。

## 流程

1. 学生点击“新建立项”，在抽屉表单填写项目名称、想解决的问题、初步方案、指导教师；团队成员为选填。
2. 前端调用 `POST /api/proposals/` 创建 `pending` 立项申请；学生工作台显示“等待教师立项审核”，不能创建正式材料。
3. 教师通过既有 `POST /api/proposals/{id}/approve/` 审批后，服务端创建正式项目并返回关联项目。学生刷新或重新进入工作台可从 `/api/projects/` 获取项目。
4. 学生在项目中打开“开题报告”。系统为项目创建或读取名为“开题报告”的 `Material`，学生可编辑其最新草稿 `MaterialRevision`。
5. AI 助手只在右侧抽屉生成可编辑预览文本。学生点击“采用到开题草稿”后，预览文本被追加/写入编辑区；AI 不直接创建提交版本、不自动改变材料状态。
6. 学生勾选“内容已按真实项目过程核对”后，才可调用 `POST /api/material-revisions/{id}/submit/`。成功后显示待教师审核、提交时间和当前版本。

## 接口与数据补充

- 增加 `GET /api/me/`，返回 `id`、`username`、`role`、`school`、`must_change_password`，供前端自动进入学生端；保留页面角色选择器仅用于无登录的演示模式。
- 为立项申请新增 `teacher` 可选关联字段；学生必须提交同校教师 ID，审批操作只能由被选择的指导教师或学校管理员执行。
- `ProjectViewSet` 的学生列表仅返回学生参与/负责的项目，教师仅返回主指导项目，学校管理员返回本校项目；避免本校所有学生互相可浏览项目。
- 前端 API 模块新增 `getMe`、`getProposals`、`createProposal`、`getProjects`、`createMaterial`、`createMaterialRevision`、`submitMaterialRevision`。请求失败时显示明确的登录/保存失败提示，不伪造成功状态。
- 本轮 AI 继续使用前端本地预览文本；每次采用将把提示目标与草稿内容保存进材料版本，不接入真实模型调用或 AI 日志创建。

## 页面与交互

- 学生工作台的“新建立项”打开表单抽屉；提交成功后原地替换为申请状态卡。
- 如果存在正式项目，主卡显示项目名称、开题报告状态和“编辑开题报告”操作；如果仅有 pending 申请，显示等待审核、不可提交材料。
- 开题报告使用右侧抽屉：富文本简化为多行文本编辑、AI 建议预览/采用、真实性复选框、保存草稿、提交审核。
- 所有保存/提交操作用 Element Plus loading 与消息反馈；抽屉关闭前未保存内容提示用户。

## 验收

- 学生创建立项申请后刷新页面仍可看到等待审核状态。
- 学生不能提交缺少必填字段或非本校教师的申请。
- 被审批的学生可看到正式项目，并可创建、保存、编辑开题报告草稿。
- AI 预览在点击采用前不改动材料；采用后草稿内容改变。
- 未勾选真实性确认时提交被前后端阻止；勾选后材料状态为 submitted，刷新仍可见。
- 学生不能用 API 查看未参与的项目、其他学校项目或提交其他人的材料版本。
