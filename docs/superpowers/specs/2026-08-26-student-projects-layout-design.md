# 学生“我的项目”A 方案设计规格

## 目标

让学生打开“我的项目”时先看到当前真正要继续推进的项目，同时保留对其他项目的分页管理能力。页面仍然使用方案 B 的浅色纸张、苔绿色强调、系统无衬线字体和统一控件，不改变路由、权限、项目生命周期接口或创建流程。

## 页面层级

1. 页面标题区：保留“我的项目”、职责描述和唯一的“新建项目”主动作。
2. 生命周期区：进行中、已归档、回收站三个标签继续控制数据集合。
3. 当前项目区：仅在“进行中”且没有搜索词时展示主项目；若没有主项目，则展示当前进行中的第一项目作为“待继续项目”。大卡突出项目名称、研究问题、初步方案、状态、成员、指导教师、创建时间和下一步入口。
4. 项目网格区：标题为“其他项目”，双列纸张卡片按页展示 6 条；每张卡片显示名称、类型、状态、问题摘要、成员、指导教师、时间和生命周期菜单。当前项目不在该区重复展示。
5. 搜索态：输入关键词后隐藏当前项目区，搜索结果包含当前项目，计数和分页针对全部匹配结果，避免用户误以为搜索漏掉项目。
6. 归档/回收站：不展示当前项目区，直接展示对应生命周期的项目网格和分页。

## 交互契约

- 当前项目主按钮进入 `studentProjectRoute(project.id)`，不新增路由。
- 项目网格的进入、继续编辑、查看存档、查看项目和生命周期菜单复用现有行为。
- 当前项目大卡保留项目管理菜单，确保设为主项目、归档、回收站等操作不会被隐藏。
- 没有项目、加载中、加载失败、无搜索结果继续使用现有空状态、反馈和重试机制。
- 指导教师优先展示 `primary_teacher_name`，没有指导教师时显示“待认领”。

## 视觉规则

- 当前项目大卡跨内容区全宽，采用浅苔绿色渐变和左侧状态标识，标题字号高于列表卡片。
- 项目网格使用两列，卡片内部按“身份 / 研究摘要 / 事实与操作”排列，动作区固定在底部，避免标题或问题长度挤压按钮。
- 1280px 与 1440px 使用相同结构，不增加移动端布局；只允许内容在卡片内部换行，不产生页面级横向滚动。
