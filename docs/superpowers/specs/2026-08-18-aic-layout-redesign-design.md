# 灵思 AI 中心布局重构设计规范（意图 D + Composer D2）

## 背景与目标

灵思 AI 中心（AICenter.vue）是学生端最高频页面，但目前存在四个结构性体验问题：

1. **顶部浪费空间**：研究旅程阶段 Tabs + Agent Pills 纵向堆叠，16 个「成果整理」类 Agent 进入折叠菜单，用户无法扫读能力。
2. **左侧树交互猜谜**："当前步骤"用文字标签挤占一行；"加入参考"依赖隐藏 Checkbox，无人能发现。
3. **系统 Prompt 外露**：一致性检查等高级 Agent 直接把 JSON 甩给学生看，被用户反馈为"什么情况？"。
4. **底部输入框 5 层堆叠**：快捷 Chips → 变量 Toggle → Textarea → 提交行 → 配额 Banner，静态高度 ~240px，聊天区实际只够装 2~3 轮对话。

本次重构的目标：**同屏密度提升 30%，分类理解从 3 步降到 1 步**。学生不滚动就能看到：
- 当前步骤上下文
- 8~12 个 Agent 卡片（不用折叠）
- 3 轮完整对话
- 可直接输入的紧凑编辑器

## 用户意图模型（改动① · 方案 D）

### 分类维度调整

**原分类（弃用）**：按研究旅程阶段分类 Agent → "成果整理"阶段有 16 个 Agent，其它阶段 3~5 个，分布极不均匀，通用能力（润色、数据分析）归属冲突。

**新分类（采用）**：按**用户意图** 4 Tab + **研究旅程**作为二级过滤 Chips。

| 意图 Tab | 用户语义 | Agent 数量目标 | 示例成员 |
| --- | --- | --- | --- |
| 💡 想思路 | 还没动笔，需要启发方向、结构、问题 | 2~4 | 选题建议、结构大纲、问题澄清、问卷选题 |
| ✍️ 起草稿 | 已经有材料，直接生成段落或章节初稿 | 3~5 | 报告起草、图表说明、背景段扩写、参考文献描述 |
| 🧹 加工稿 | 已有文字，需要润色/扩充/改写/整理格式 | 3~5 | 文本润色、数据分析解读、参考文献规范化、格式校对 |
| 🔍 做检查 | 内容自查，发现漏洞、冲突、缺失 | 2~3 | 一致性检查、证据完整性、学术规范 |

研究旅程（立项/方案/制作/成果整理/答辩）从主分类降级为**二级过滤 Chips**，仅用于"仅看某阶段适用的 Agent"。它是可选过滤，不是强制必选。

### 视觉布局

中栏顶部由上至下依次为：
1. **意图 Tab 栏**（4 Tab，固定顺序）：每项 Tab 右上角胶囊显示 Agent 数量；激活态 = 苔藓绿下划线 + 深色文字 + 深色胶囊数字。
2. **研究旅程过滤 Chips 行**：`"仅看阶段"` 文字标签 + 不限（×/ghost）+ 阶段 chip。激活 chip 苔藓绿填充 + 黑色小点图标 + 该阶段步骤数。
3. **Agent 卡片网格**：`auto-fill, minmax(164px, 1fr)`，每张卡片高约 84px，包含：
   - 名称行：Emoji + 名称 + 右上角 ✓（激活态）
   - 描述：两行省略
   - 分类色 Chip：idea/write/edit/check 四色（紫罗兰/苔藓/灰蓝/琥珀）
   - 激活态：苔藓绿边框 + 浅苔藓背景 + ✓ 图标

同一意图下，最多同时可见 8~12 张 Agent 卡（1680px 宽度 5 列可装 10；1280px 宽 4 列可装 8），无需折叠菜单。

### 交互行为

- 切换意图 Tab 立即刷新网格内容，不保留旧选择；旅程过滤 chip 可与意图叠加。
- Agent 卡支持点选切换，卡内出现 ✓；底部 Composer 的顶栏当前助手胶囊也随之刷新。
- 空态（意图 × 阶段 的交集为空）：显示 EmptyState，文案 "该意图暂无适配「阶段 X」的助手，尝试 × 不限 或 切换其他意图"。

### 后端语义约束

- 每个 `AgentTemplate` 新增字段 `intent_category`（idea / write / edit / check，必需）。
- 原有的 `applicable_stages` 保留，用于二级过滤器。
- 研究旅程未开始的阶段，对应 stage chip 不自动过滤（保持用户可探索）。

## 项目旅程树交互（改动② · 左栏修复）

### 顶部必须加 3 色图例

| 标记 | 颜色 | 含义 |
| --- | --- | --- |
| 实线色块 | 苔藓绿 #5d7a44 | 当前步骤（左栏色条 + 右栏必带项） |
| 空心方框 | 苔藓绿描边 | 已选择作为 AI 参考中的步骤/材料 |
| 实心圆点 | 浅苔色 #c2cfb0 | 该步骤下有已上传的材料（材料可参考） |

### 当前步骤：取消文字标签，改用 3px 色条

- 原版："当前步骤：XXX"作为文字标签挤占一行 → **删除**。
- 新版：该步骤行的最左侧加 3px 宽苔藓绿竖条（`::before`），步骤名颜色加深到 `#2f3f22` 加粗，背景为 `#eef2e3`。
- 语义：**任何时间只有一个"当前步骤"**，由 `interactionModel.currentStepId` 决定。

### 加入参考："+参考"按钮 hover 出现，选中后常驻

- 原版：Checkbox 隐藏在行尾 → **删除**。
- 新版：每行步骤的行尾有 `+参考` 按钮，**只有 hover 步骤行时才出现**。
- 点击后按钮改为常驻态：白背景 + 苔藓绿描边 + ✓ 图标 + "参考"文字，字体加粗。
- 选中后，右栏「作参考的步骤与材料」区块新增对应条目，Composer 底栏 `ctx-mchip` 新增一粒 `+ XXX`。
- 已有材料的步骤的参考按钮用 "● +参考"（有材料提示，不强制）。

### 阶段头

- 每阶段头右侧用 mini-tag 显示进度：进行中 = "进行中" 蓝灰胶囊；已完成 = "X/X" 完成胶囊；未开始 = "待开始" 灰胶囊。
- 已完成阶段默认折叠为 `▸`，当前阶段默认展开 `▾`；空阶段和未开始阶段名称自动降饱和（opacity 60%）。

### 验收信号

- 初次加载：当前步骤有左边条，hover 任意非当前步骤行即出现 `+参考` 按钮。
- 已选择参考的步骤：无 hover 状态下也可见 "✓ 参考"。
- 左栏选择 / 取消参考时，右栏「上下文」和底部 Composer 底栏 chips 都在同一帧更新。

## AI 响应中技术细节不外露（改动③）

### 适用范围

以下 Agent 返回的内容在界面上必须先做"友好化包装"，原始 JSON 默认隐藏：
- 一致性检查（ConsistencyCheckCard）
- 证据完整性检查
- 学术规范检查
- 以及所有会返回 `debug_prompt`、`raw_sources` 字段的 Agent

### 通用摘要卡结构

所有结构化检查结果统一呈现为：**外层 Amber 背景卡**（暖米黄边 + 琥珀描边），内部按以下分区：

1. **标题行**：
   - 左侧 Emoji（🛡 一致性 / ✳ 证据完整性 / ⚖️ 学术规范）+ 类型名 + 「结果摘要」
   - 右侧「查看原始 JSON ↓」按钮（打开折叠面板，等同于下面 details）
2. **K/V 列表**（`dl.grid`）：
   - `证据覆盖分 / 完成度分 / 规范分数` 任一可数值化的维度 → `score 胶囊`：苔藓绿底、分数 + /100
   - `缺关键证据 / 高风险项 / 冲突` 等列表维度 → 以逗号或分号分隔的短句
3. **问题清单**（如有）：`ul.issue-bullet`，每项必须：
   - 开头优先级标签 `高/中/低`：陶土色 / 琥珀色 / 浅灰底
   - 问题标题 + 涉及材料
   - 可落地的"建议写法"，优先用 `code` 包裹示例片段，长度限制在一行完整可阅读
4. **原始 JSON**：`<details>` 折叠面板，默认关闭，内等宽字体显示原始返回体

### 引用上下文来源区

摘要卡下方固定显示来源 tags："📋 步骤 · XX" 或 "📎 文件名"，与对话 meta 行区分开。

### 与后端 / ConsistencyCheckCard.vue 的关系

- `ConsistencyCheckCard.vue` 是本规范的第一个样板组件，必须按上述结构重写。
- 后端 `ai.py` 中返回的 `consistency_result` schema 保持不变；新字段如 `coverage_score` 可在前端兜底缺省。
- 原始 JSON 折叠面板仅作为兜底调试视图，**移动端可省略**。

## Composer（改动④ · 方案 D2 · Floating Toolbar）

### 结构与尺寸

Composer 固定为**一张圆角卡片**，替代原来的 5 行堆叠。内部 3 段式：

```
┌──────────────────────────────────────────────────────────┐
│ [✨润色] [📈续写] [🧱结构] [🔗一致性] | [📋3变量] | [🧠上下文 5]  | 📝研究报告起草 [▾] │  顶工具栏
├──────────────────────────────────────────────────────────┤
│ 多行文本输入框 · min-height 96px                           │
│                                                           │
│ 上下文自动带入 · 5 项（静态提示块）                          │
├──────────────────────────────────────────────────────────┤
│ ◉图表制作  +①数据分析  +✦背景调研  +2材料       │ 配额 73 次 │ ➤发送 ⌘↩ │  底栏
└──────────────────────────────────────────────────────────┘
```

- 总最小高度 ~156px，比原版 ~240px 节省 84px。
- 顶工具栏、底栏高度均不超过 38px；textarea 至少保留 80px 可书写空间。

### 顶工具栏（Floating Toolbar）

| 元素 | 含义 | 行为 |
| --- | --- | --- |
| `✨润色 / 📈续写 / 🧱结构 / 🔗一致性` | 快捷宏 | 点击后在 textarea 前缀插入对应系统提示片段，光标留在尾部 |
| `📋 3 变量` | 变量入口 | 点击打开变量抽屉（复用原有变量 UI），变量数量反映当前项目可替换词个数 |
| `🧠 上下文 N` | 上下文数查看 | 点击跳到右栏上下文 Tab，并滚动高亮当前步骤卡片 |
| `📝 研究报告起草 ▾` | 当前助手胶囊 | 点击打开 Agent 切换下拉（快速替换，不必滚到顶部点网格） |

顶栏使用 d2-sep（1px 细灰色分隔线）分组：快捷宏一组 / 变量一组 / 上下文一组 / 当前助手在最右。

### 中间 Textarea

- 无 label，无标题行，placeholder 直接写"给 AI 说点什么…（⌘↩ 发送）"。
- 内置上下文**自动注入块**（textarea 内底部的浅苔色左边条卡片）：
  - `◉ 当前步骤：名称、对应报告章节`
  - `🔗 参考步骤：已勾选的 N 项`
  - `📎 参考材料：文件 1 · 文件 2 …`
- 该块为只读视觉信息，发送时内容实际附加在 system prompt，**不写入用户可见的消息文本**。
- 支持 `Shift + Enter` 换行，`⌘↩` / `Ctrl + Enter` 发送。

### 底栏

左侧：**上下文 chips 横排**
- `◉ XX` = 当前步骤（苔藓绿实心胶囊，加粗，不可删除）
- `+ XX` = 已勾选参考步骤/材料（点击对应项上 × 删除）
- 超过 3 项则后面合并为「+N 材料」chip，点开显示所有项列表（后续可升级为 tooltip）

右侧：
- `配额 73 次` 胶囊：复用原有配额值，颜色蓝，显示整数
- `➤ 发送 ⌘↩` 按钮：苔藓绿填充，白色文字，包含 kbd 样式快捷键提示

### 输入状态机

| 状态 | 发送按钮 | 视觉 |
| --- | --- | --- |
| 空 + 无上下文 | 禁用，灰色 | D2-wrap 边框浅灰 |
| 有文字或有上下文 | 激活，苔藓绿 | D2-wrap 边框苔藓 + 3px 淡色外环 |
| 发送中 | 文案变为"发送中…"，按钮禁用并进入加载态 | 显示发送进度指示器（后续可加入 token 消耗） |
| AI 返回中 | 新消息气泡显示"思考中…"pending 状态 | 按钮恢复激活，text area 清空 |

## 三栏整体信息架构约束

### 各栏"只解决一个问题"

| 栏 | 只回答的用户问题 | 不承担 |
| --- | --- | --- |
| 左栏 228px | 我的项目旅程处于哪个阶段？**从这里勾选要作为 AI 参考的步骤/材料**（单一操作权威） | 不编辑材料、不展示成员 |
| 中栏 1fr | 跟 AI 对话解决当前任务 | 不装完整项目详情、不装完整材料列表 |
| 右栏 280px | AI 现在能读到什么上下文？**按权重排序后的只读检视** | 不提供增删操作、不承担步骤编辑 |

### 单一操作权威（解决左右栏双写冲突）

用户反馈的核心冲突："两边都能改的话，我不知道谁说了算，万一不同步怎么办？"。本规范采用 **左为权威（单一采集入口）、右为只读（单向检视）** 的不对称分工，彻底消除双写。

| 操作 | 左栏 tree | 右栏 context | Composer 底栏 chips |
| --- | --- | --- | --- |
| 加入某步骤/材料为参考 | ✅ `hover 行 → +参考`，唯一入口 | ❌ 不提供"加"入口 | ❌ 不提供"加"入口 |
| 取消已勾选的参考 | ✅ hover 已选步骤行 → 点击常驻的「✓ 参考」切换为未选，唯一入口 | ❌ 完全移除 ctx-item 行尾的 × 删除按钮 | ❌ 移除 chips 的可删除交互（chips 只作为信息扫读，当前步骤 ◉ 永远保留） |
| 查看当前 AI 读取范围 + 权重 | ❌ 只显示"该步骤是否参考"的二值状态，不按权重排 | ✅ 顶部显示当前必带步骤卡 + 已勾选参考项，明确标出权重从高到低（当前步骤 > 最近步骤 > 归档步骤 > 材料） | ✅ 同步显示 chips 摘要，「+N 材料」点开可看全文 |
| 发现想取消的项不在视野 | hover 对应步骤行即可 | 每段底部有提示："从左侧项目旅程 hover 步骤行，点「✓ 参考」可取消" | — |

**为什么不允许双写**：两边都允许删会出现以下坏情况——(a) 用户在右栏删了 A，回头在左栏看 A 还显示「✓ 参考」，立刻怀疑"到底删了没"；(b) 异步状态更新慢时，两边瞬态不一致引发用户恐慌点击；(c) 移动端双端操作不一致时 bug 难以回溯。

**为什么权威放在左而非右**：参考选择的语义起点是"我有这个步骤/材料想让 AI 知道"，最自然就是在步骤出现的地方勾选。右栏如果作为权威，需要额外引入「选择对话框 / 搜索框」等控件，与现有 Tree 结构重复且更重。

### 固定视觉优先级

1. 苔藓绿强调 = "当前步骤"（左栏色条、Composer ◉ 胶囊、右栏必带卡）
2. 浅苔 + 勾选 = "已经选为参考"（左栏 +参考 常驻、Composer + Chips、右栏 ctx-item）
3. 琥珀卡 = "检查类摘要结果"（改动③ 仅出现在 AI 气泡内）
4. 紫胶囊 / 分类色 = Agent 的意图归属（帮助扫读，不参与状态）

### 响应式断点

- **≥1440px**：左 228 / 中 1fr / 右 280，保持三栏
- **1280px**：左 216 / 中 1fr / 右 260，Agent 网格 4 列
- **<1200px（窄屏）**：右栏可折叠为抽屉，Composer 顶栏和底栏 chips 支持折行；不允许出现横向滚动条

## 验收标准

1. **分类扫读**：在 1680px 宽度下，激活任一意图 Tab 后能同时看到至少 8 张 Agent 卡，无需滚动或点击"更多"。
2. **Tree 学习成本为 0**：新用户首次进入页面，通过左栏 3 色图例能立刻理解"当前 / 参考 / 有材料"三种标记的差别。
3. **当前步骤无文字标签占用行**：左栏没有任何"当前步骤：XXX"的说明文字，仅靠 3px 色条 + 加粗 + 背景即可识别。
4. **+参考 交互可发现**：hover 任意步骤行即出现按钮；已参考步骤在无 hover 状态下也可见常驻标记。
5. **Prompt 不外露**：一致性检查类 Agent 的对话内容中，默认看不到 JSON；只有主动点 details 或「查看原始 JSON ↓」才能展开。
6. **摘要卡信息完整**：摘要卡必须同时包含分数、缺失项、问题优先级、可直接复制的建议写法；不得只给分数不给行动。
7. **Composer 高度 ≤ 168px**（包含 1px 上下边距与 textarea min-height 96px），聊天可见区域比原版多出至少 72px。
8. **上下文双向同步**：左栏点 "+参考"、右栏点 ×、Composer 底栏 chips 点 ×，三种操作在同一帧内互相同步。
9. **⌘↩ / Ctrl+Enter 发送**在 textarea 任何光标位置均可触发，不会误触其他快捷键。
10. **空态可见性**：输入框无文字 + 无上下文时发送按钮必须禁用；任一条件满足即恢复。
11. **1280px 和 1440px 均无横向溢出**；Composer 顶/底栏在窄屏下可折行，但不能破坏三段结构。
12. **原有功能不丢失**：变量抽屉、配额显示、快速宏、对话历史、发送 loading/pending 状态均需保留并做回归验证。
