# 灵思 AI 历史会话永久删除设计

## 目标

在灵思 AI 的历史会话抽屉中提供明确的永久删除能力，让学生可以清理误建、测试或不再需要的会话。删除必须是显式确认后的破坏性操作，并且不影响其他会话的打开与筛选。

## 交互设计

### 删除入口

- 每条历史会话记录增加一个删除按钮，放在记录右侧，不改变现有标题、日期、项目和状态信息。
- 删除按钮在记录悬停或获得焦点时显示，键盘用户可以直接访问；按钮使用会话标题生成可读的无障碍名称。
- 点击删除按钮只打开确认，不触发该记录的选择或恢复。

### 二次确认

- 确认框显示会话标题，并明确提示“删除后对话和消息不可恢复”。
- “取消”关闭确认框并保持历史列表不变。
- “永久删除”按钮在请求期间禁用，避免重复提交。
- 按 Escape 或点击遮罩关闭确认框。

### 删除后的状态

- 删除非当前会话：从列表中移除该记录，保留历史抽屉、当前模式筛选和搜索条件。
- 删除当前会话：删除成功后关闭确认框和历史抽屉，清空当前消息与会话选择，并回到当前模式的新建态。
- 删除失败：关闭请求状态，保留原记录和当前会话，并在抽屉内显示错误提示。
- 已归档会话也允许永久删除；“查看已归档”只负责显示/隐藏，不改变删除语义。

## 数据与接口

- 前端新增 `deleteAIConversation(id)`，调用 `DELETE /api/ai-conversations/:id/`。
- 后端会话 ViewSet 开放 `DELETE` 方法，沿用现有 queryset 权限边界，学生只能删除自己的会话，教师只能删除自己负责项目下的指导会话。
- 删除 `AIConversation` 时级联删除其消息；生成日志属于审计数据，保留日志但解除会话和消息关联。
- 删除成功返回 `204 No Content`，前端以本地列表更新为主，不额外依赖返回对象。

## 组件边界

- `AIConversationHistory.vue` 负责删除按钮、确认框、确认状态和删除事件的发出。
- `AICenter.vue` 负责调用 API、更新会话集合、处理当前会话清理和错误提示。
- `api.ts` 只负责提供类型化的删除请求，不承载页面状态。
- 后端 `AIConversationViewSet` 只负责授权与删除数据，不改变现有历史标题、筛选和归档逻辑。

## 验收与测试

- 定向前端契约测试覆盖：删除按钮、确认文案、取消/确认事件、当前会话处理入口和 API 方法。
- 定向后端测试覆盖：本人会话可删除、他人会话不可见、消息级联删除、生成日志保留且解除关联、已归档会话可删除。
- 浏览器手动验证：删除非当前会话、删除当前会话、取消删除、Escape 关闭、删除失败提示，以及已归档会话删除。
- 本轮不执行全量测试，不增加移动端适配范围。
