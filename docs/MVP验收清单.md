# 灵溯单校 MVP 验收清单

## 0. 验收前准备

后端 `.env` 仅在本机或部署环境设置密钥，不提交到 Git：

```env
ARK_API_KEY=替换为服务商密钥
OPENAI_BASE_URL=https://openrouter.ai/api/v1
OPENAI_MODEL=openrouter/free
```

重启后端、Celery worker 和前端，确认 `/api/service-status/` 的 `ai` 为 `configured`。密钥不会返回前端。

准备三个账号：学生、指导教师、平台管理员；另准备一个不同学校的学生账号用于隔离验证。

## 1. 管理员发布内容

- 使用平台管理员进入“赛事管理”，创建并发布一项赛事。
- 进入“平台公告”，创建并发布一条公告。
- 用学生和教师账号打开赛事、公告内容中心，确认已发布内容可见。
- 管理员创建一条草稿内容，确认普通账号不可见；停用后确认普通账号列表不再显示。

## 2. 项目创建与教师认领

- 学生进入“项目书架”，创建项目，填写题目、研究问题和方案概要。
- 教师进入项目池，认领该项目。
- 学生确认项目进入固定研究旅程，并能看到至少一项可开始任务。

## 3. 材料退回、重提与通过

- 学生填写第一项材料，勾选“已按真实项目核对”，提交审核。
- 教师在审核队列退回材料并填写具体意见。
- 学生确认页面保留退回意见，修改内容后重新提交。
- 教师通过材料；确认旧版本仍可追溯，任务状态进入已通过/完成。

## 4. 真实 AI 与材料草稿

- 学生在 AI 中心选择该项目和 Agent，发送一个与项目相关的问题。
- 确认生成记录状态从排队/处理中进入完成，并显示真实模型名称。
- 编辑生成结果，明确选择目标材料后保存。
- 确认材料新增一条草稿版本；AI 不会自动提交材料或执行审核。
- 若返回 401、429、502、503 或超时，页面应显示可理解的错误并允许重试。

## 5. DOCX/PDF 报告

- 在已通过材料的项目报告页分别发起 DOCX 和 PDF 导出。
- 确认页面显示排队、处理中和完成状态。
- 下载并打开两个文件，确认正文来自最新已通过版本。
- 临时停止 Gotenberg 后重试 PDF，确认导出记录为失败而不是完成，并可再次发起。

## 6. 公开案例治理

- 将项目所需材料全部通过并完成项目。
- 学生提交公开案例申请，只选择已通过且允许公开的材料。
- 教师初审通过；管理员在案例治理中发布。
- 学生查看已发布案例，管理员执行下线和再次发布，确认历史申请与审核记录保留。

## 7. 跨校隔离

使用不同学校学生账号验证以下请求均不可读取：

- 项目详情和材料版本；
- 附件下载地址；
- AI 对话和生成记录；
- DOCX/PDF 报告下载。

验收结论：以上 1–7 全部通过，才标记“灵溯全项目 MVP 完成”。
